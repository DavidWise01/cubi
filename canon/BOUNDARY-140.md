# CUBI 140 — Isolated Hemispheres, Recursive Diodic Pool

Canonical substrate: `{{aether}}`, rectangle `{ [6x4(5x3)] }`.

Three isolated hemispheres are `{{lh:: observe, aware, action, reaction, compare}}`, `{{ch:: observe, aware, action, reaction, compare}}`, `{{rh:: observe, aware, action, reaction, compare}}`, contained in one enclosing BOX. Each hemisphere has six slots (1/6 × 6), dual polarity `[(-+)]`, and five named functions. No hemisphere's internal parent pointers cross into another hemisphere. The route `a/\\b/c\\/data` is preserved literally as a routing token pending precise operator semantics.

Each manually triggered cycle appends six isolated records per hemisphere, 18 in total, to the common IndexedDB pool in a single transaction. A read-only audit checks completeness, isolated parent chains, and closed doors. The sixth slot currently reuses observe; the domain semantics of the sixth position are not canonized. The pool co-locates, not blends, separate records; recursive parent links are currently cycle-local rather than across generations. The implementation is symbolic, does not execute arbitrary tools, does not make autonomous decisions, and has not been live-tested in Chromium. No quorum or consensus.
